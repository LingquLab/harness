# 中文技术表述

- 写清谁做什么、操作哪个对象。涉及代码时，先读实现，再写参数、调用、等待条件、资源归属或释放顺序。例如“校验参数”“创建 communicator”“等待 stream 完成”“调用 cleanup”“释放 buffer”。只写有依据的动作和顺序。
- 保留英文技术术语和标识符，例如 `token`、`opaque handle`、`communicator`、`rank`、`stream`。读者需要背景时，用自然中文解释其用途。例如“调用方通过 opaque handle 引用对象，无法直接访问对象内部”。
- 双语注释表达同样的行为，两种语言各自按自然语序写。
- 命中黑名单后，按句子的实际含义改写。有时需要补上动作和对象，有时删掉空话即可。正式名称、必须保留的引文和准确的领域用语按上下文保留，例如仲裁文书中的“裁决”。

## 交付前自查

用 Python 3 运行 [扫描脚本](scripts/scan.py)，检查本次写的中文草稿。将 `SKILL_DIR` 设为本 skill 的目录。脚本接受 UTF-8 文件或标准输入。

```bash
python3 "$SKILL_DIR/scripts/scan.py" draft.md
printf '%s\n' '先校验参数，再创建 communicator。' | python3 "$SKILL_DIR/scripts/scan.py"
```

脚本逐字匹配[词汇黑名单](references/blacklist.json)，输出行号、列号、命中词和改写提示。行号和列号从 1 开始。更新黑名单时，在 JSON 中增删词条及对应的提示。

退出码 `0` 表示无命中，`1` 表示有命中，`2` 表示扫描失败。逐条处理命中，修改后复扫，再通读一遍，检查动作是否明确、术语是否一致、描述是否符合实现。脚本无法运行时，直接对照黑名单自查。
